# 속담·사자성어 50문항 데이터 전달 사항

> **일부 내용은 지나간 것입니다.** 이 문서는 데이터를 넘겨받던 시점의 기록이며,
> "방을 만들 때 모드를 고른다"는 전제는 더 이상 맞지 않습니다. 지금은 한 방이
> 노래·속담·사자성어를 순서대로 모두 진행하고, 방장은 챕터별 문제 수만 정합니다
> (기본 30문항). 데이터 형식과 검수 기준은 그대로 유효합니다. 현재 규칙은
> [`../docs/GAME_RULES.md`](../docs/GAME_RULES.md)에 있습니다.

## 파일

- `data/proverbs.50.json`: 속담 50문항
- `data/idioms.50.json`: 사자성어 50문항

두 파일은 현재 Claude 구현안의 `RawProverb`와 `RawIdiom` 필드를 그대로
포함한다. `difficulty`와 `explanation`은 추가 메타데이터이므로 TypeScript에서
필요하지 않으면 무시해도 되고, 문제 선택 및 정답 공개 화면에 활용해도 된다.

## 구현 시 반드시 변경할 부분

문제 은행은 모드별 50문항이지만, 한 게임에서는 그중 30문항만 무작위로
선택하여 출제한다. 현재 Claude 작업안의 게임당 30문항 규칙은 유지하고 문제
은행 크기와 게임당 출제 수를 별도 상수로 구분한다.

1. 문제 은행 검증 수는 50, `QUESTIONS_PER_TEXT_GAME`은 30으로 설정한다.
2. 서버가 읽는 파일을 이 두 파일로 지정하거나, 검증 후 기존
   `data/proverbs.json`과 `data/idioms.json`을 이 파일 내용으로 교체한다.
3. 방을 만들 때 해당 모드의 50문항을 섞고 앞의 30문항만 선택한다.
4. 한 게임 안에서는 같은 문항을 중복 출제하지 않는다. 새 방을 만들 때마다
   다시 무작위로 선택하므로 방마다 문제 조합과 순서가 달라질 수 있다.
5. 클라이언트의 진행 표시는 `현재 문제 / 30`을 유지한다.
6. 테스트는 문제 은행 50문항과 게임당 30문항을 각각 검증한다.
7. 게임은 선택된 30문항을 모두 한 번씩 출제한 뒤 종료한다.

## 문제 공개 및 정답 판정

- 속담 문제 중에는 `prefix`만 공개한다. 정답으로 `suffix`, `full`, `aliases`를
  인정한다.
- 사자성어 문제 중에는 `meaning`만 공개한다. 정답으로 `answer`, `hanja`,
  `aliases`를 인정한다.
- `full`, `suffix`, `answer`, `hanja`, `aliases`, `explanation`은 정답 공개 전
  클라이언트 페이로드에 포함하지 않는다.
- 기존 정답 정규화기를 사용하고 유사 문자열 퍼지 매칭은 추가하지 않는다.

## 난이도

두 파일의 50문항은 모두 일반 참가자가 단서를 보고 맞힐 수 있는 `medium`
난이도로 통일했다. 서버는 별도의 난이도 가중치 없이 50문항 전체를 섞은 뒤
30문항을 뽑는다.

## 검수 기준

- 파일별 문항 수 50개
- 모든 문항의 `difficulty` 값이 `medium`임
- 게임별 무작위 선택 수 30개
- 한 게임 안의 문항 ID 30개가 모두 고유함
- ID와 대표 정답 중복 없음
- 속담의 `prefix`와 `suffix`를 붙이면 `full`이 됨
- 사자성어 한글 정답과 한자 표기는 각각 네 글자
- 문제로 공개되는 단서에 정답 문자열이 포함되지 않음
