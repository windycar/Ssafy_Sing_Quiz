# 곡 데이터 가이드

게임에 쓰이는 곡 목록을 만들고 검수하는 방법입니다. 대상 독자는 곡을 등록·검수하는
운영자와, 곡 데이터를 읽어 들이는 코드를 작성하는 개발자입니다.

## 1. 복구된 SCX 카탈로그 현황

곡 목록의 출발점은 스타크래프트 맵 파일(`.scx`)에서 복구한 텍스트입니다. 복구 과정과
제약은 `docs/scx-recovery.md`(`agent/codex` 브랜치)에 기록되어 있고, 결과물은
`data/songs.recovered.json`(`agent/codex` 브랜치)에 있습니다.

| 항목 | 값 |
| --- | --- |
| 복구된 곡 수 | 171곡 |
| `mediaUrl`이 비어 있는 곡 | 171곡 (전부) |
| `clipStart` / `clipEnd`가 비어 있는 곡 | 171곡 (전부) |
| `aliases`가 제목 하나뿐인 곡 | 171곡 (전부) |
| 제목에 괄호가 들어간 곡 | 47곡 |
| 곡 제목 정규화 후 서로 겹치는 곡 | 0건 |

### 반드시 알아야 할 세 가지 한계

1. **지금 이 파일만으로는 게임을 한 판도 돌릴 수 없습니다.**
   음원 URL과 재생 구간이 전부 비어 있어, 검증기를 돌리면 171곡 모두
   `MISSING_MEDIA_URL`로 걸러집니다. 운영자가 값을 채워야 합니다.

2. **SCX에 들어 있던 오디오는 어떤 경우에도 추출·재배포하지 않습니다.**
   복구 스크립트는 텍스트만 훑습니다(`tools/extract-scx-song-text.py`). 맵 안에
   오디오가 들어 있더라도 그것을 꺼내 서버에 올리는 것은 이 프로젝트의 범위가 아니며,
   허용되지 않습니다. 음원은 **별도로 이용 허락을 받은 출처**에서 가져와야 합니다.

3. **복구 텍스트는 아직 사람이 검수하지 않았습니다.**
   원본 맵의 문자열 일부가 잘려 있어, 제목이나 아티스트가 부정확할 수 있습니다.
   [7. 검수 체크리스트](#7-검수-체크리스트)를 따라 확인한 뒤 사용하세요.

## 2. JSON 구조

### 2-1. 파일 형태

```json
{
  "count": 171,
  "songs": [ /* 곡 레코드 배열 */ ]
}
```

### 2-2. 곡 레코드 필드

| 필드 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- |
| `id` | string | 필수 | 곡을 구분하는 고유 문자열. 복구본은 `scx-001` 형식입니다. |
| `artist` | string | 필수 | 아티스트명. 정답 판정에는 쓰이지 않고 정답 공개 화면에만 표시됩니다. |
| `title` | string | 필수 | 곡 제목. 정답 별칭의 기준이 됩니다. |
| `aliases` | string[] | 선택 | 추가로 인정할 정답 표기. 제목에서 자동으로 만들어지는 별칭에 **더해서** 적용됩니다. |
| `mediaUrl` | string \| null | 게임 진행에 필수 | 재생할 음원 주소. 복구본은 전부 `null`입니다. |
| `clipStart` | number \| null | 게임 진행에 필수 | 재생 시작 지점(**초** 단위). |
| `clipEnd` | number \| null | 게임 진행에 필수 | 재생 종료 지점(**초** 단위). |
| `source` | string | 선택 | 출처 메모. 복구본은 `"scenario.chk UTF-8 recovery"`입니다. |

> **단위 주의.** 데이터 파일은 `clipStart`/`clipEnd`를 **초**로 적습니다.
> 서버 내부 규격([`realtime-protocol.md`](./realtime-protocol.md) §1)은
> `clipStartMs`/`clipEndMs`로 **밀리초**를 씁니다. 변환은
> [`shared/songCatalog.ts`](../shared/songCatalog.ts)의 `buildSongCatalog`가 담당하므로,
> 데이터 파일을 직접 밀리초로 바꾸지 마세요.

### 2-3. 복구 직후 상태 (그대로는 사용 불가)

```json
{
  "id": "scx-005",
  "artist": "f(x)",
  "title": "피노키오 (Danger)",
  "aliases": ["피노키오 (Danger)"],
  "mediaUrl": null,
  "clipStart": null,
  "clipEnd": null,
  "source": "scenario.chk UTF-8 recovery"
}
```

### 2-4. 운영자가 값을 채운 완성 예시

```json
{
  "id": "scx-005",
  "artist": "f(x)",
  "title": "피노키오 (Danger)",
  "aliases": ["피노키오 (Danger)"],
  "mediaUrl": "https://media.example.com/clips/9f2c41a8.m4a",
  "clipStart": 48,
  "clipEnd": 58,
  "source": "라이선스 계약 2026-08 / 트랙 ID 9f2c41a8"
}
```

이 레코드는 검증을 통과하며, 인정되는 정답은 `피노키오 (Danger)`, `피노키오`,
`Danger` 세 가지가 됩니다. `aliases`에 아무것도 더 적지 않아도 그렇습니다.

## 3. 검증 규칙

`buildSongCatalog`([`shared/songCatalog.ts`](../shared/songCatalog.ts))가 곡 목록을
읽을 때 아래 규칙으로 검사합니다. 문제가 있는 곡은 목록 전체를 실패시키지 않고,
해당 곡만 제외한 뒤 사유 코드를 함께 돌려줍니다.

| 코드 | 발생 조건 | 조치 |
| --- | --- | --- |
| `MISSING_TITLE` | 제목이 비어 있음 | 제목을 채웁니다. |
| `MISSING_MEDIA_URL` | `mediaUrl`이 없거나 공백 | 이용 허락을 받은 음원 주소를 등록합니다. |
| `MISSING_CLIP_RANGE` | `clipStart` 또는 `clipEnd`가 없음 | 재생 구간을 지정합니다. |
| `CLIP_RANGE_INVALID` | `clipEnd`가 `clipStart`보다 작거나 같음, 또는 `clipStart`가 음수 | 구간을 바로잡습니다. |
| `CLIP_TOO_SHORT` | 구간이 5초 미만 | 5초 이상으로 늘립니다. |
| `CLIP_TOO_LONG` | 구간이 15초 초과 | 15초 이하로 줄입니다. |
| `DUPLICATE_ALIAS` | 다른 곡이 이미 쓰고 있는 정답과 겹침 | [5장](#5-같은-정답이-두-곡에-걸릴-때)을 참고해 구분되는 별칭을 지정합니다. |
| `NO_USABLE_ALIAS` | 정규화 후 남는 정답이 하나도 없음 | 제목이 기호뿐이거나, 모든 별칭을 다른 곡에 빼앗긴 경우입니다. |

재생 구간은 **5초 이상 15초 이하**이며, 정확히 5초와 정확히 15초는 허용됩니다.

검사 순서는 `제목 → 음원 URL → 재생 구간 → 별칭`입니다. 재생할 수 없는 곡이 정답
문자열을 먼저 차지해 정상 곡을 밀어내는 일이 없도록 일부러 이 순서로 되어 있습니다.

## 4. 별칭(정답 표기) 지침

### 4-1. 자동으로 만들어지는 별칭

제목 하나에서 아래 세 가지가 자동으로 만들어집니다(`expandTitleAliases`).

1. 제목 전체
2. 괄호 부분을 뺀 제목
3. 괄호 안의 내용

| 제목 | 자동 인정되는 정답 |
| --- | --- |
| `피노키오 (Danger)` | `피노키오 (Danger)`, `피노키오`, `Danger` |
| `사계 (Four Seasons)` | `사계 (Four Seasons)`, `사계`, `Four Seasons` |
| `Crescendo (크레셴도)` | `Crescendo (크레셴도)`, `Crescendo`, `크레셴도` |
| `뱅뱅뱅 (BANG BANG BANG)` | `뱅뱅뱅 (BANG BANG BANG)`, `뱅뱅뱅`, `BANG BANG BANG` |
| `바람났어 (Feat. 박봄)` | `바람났어 (Feat. 박봄)`, `바람났어` |
| `모노드라마 (With 유승우)` | `모노드라마 (With 유승우)`, `모노드라마` |

괄호 안이 `Feat.`, `ft.`, `featuring`, `with`, `prod.`, `inst.`, `remix`, `ver.`,
`version`으로 시작하면 **정답으로 인정하지 않습니다.** 참여 아티스트 이름을 찍어서
맞히는 일을 막기 위해서입니다.

복구된 171곡 중 47곡이 이 자동 확장의 혜택을 받습니다. 확장이 없으면 이 47곡은
정식 제목을 통째로 입력해야만 정답이 되어, 사실상 못 맞히는 문제가 됩니다.

### 4-2. 직접 추가하면 좋은 별칭

자동 확장으로 부족한 경우에만 `aliases`에 손으로 추가합니다.

- 널리 쓰이는 줄임말: `사랑을 했다` → `러브시나리오`
- 한글/영문 표기 차이: `Celebrity` → `셀러브리티`
- 흔한 다른 표기: `롤린 (Rollin')` → `rollin`

### 4-3. 별칭에 넣지 말아야 할 것

- 아티스트 이름 단독 (`방탄소년단`) — 아무 곡에나 걸릴 수 있습니다.
- `1위`, `노래`처럼 지나치게 일반적인 단어
- 가사 일부 — 저작권 문제이며, 답이 여러 개로 갈립니다.
- 오타를 미리 등록해 두는 것 — 아래 4-4 참고

### 4-4. 정규화 규칙과 "오타 허용을 넣지 않는 이유"

정답 비교 전에 모든 문자열을 다음 순서로 정규화합니다
([`shared/answerMatching.ts`](../shared/answerMatching.ts)).

1. 유니코드 NFKC 정규화 — 분리된 한글 자모를 합치고, 전각 문자를 반각으로 바꿉니다.
2. 소문자 변환 — 영문 대소문자를 구분하지 않습니다.
3. 문자와 숫자를 제외한 모든 것 제거 — 공백, 문장부호, 기호, 이모지가 사라집니다.

| 입력 | 정규화 결과 |
| --- | --- |
| `Dynamite` / `DYNAMITE!` / `dyna-mite` | `dynamite` |
| `다이나마이트` / `다이나 마이트` | `다이나마이트` |
| `Ｄｙｎａｍｉｔｅ` (전각) | `dynamite` |
| `200%` | `200` |
| `롤린 (Rollin')` | `롤린rollin` |
| `!!! ---` | (빈 문자열, 정답으로 쓸 수 없음) |

정규화 후에는 **완전히 같은지만** 비교합니다. 편집거리 기반의 오타 허용은 넣지
않았습니다. 오타 허용을 넣으면 "이 답이 정답인가"가 확률 문제가 되고, 선착순 판정의
근거가 흔들립니다. 근거는 [`claude-analysis.md`](./claude-analysis.md) §8에 있습니다.
오타를 별칭으로 미리 등록하는 것도 같은 이유로 권하지 않습니다. 정말 필요하면
별칭 한두 개를 명시적으로 추가하는 편이 낫습니다.

## 5. 같은 정답이 두 곡에 걸릴 때

서로 다른 두 곡이 같은 정답 문자열을 갖게 되면, **먼저 등록된 곡**이 그 문자열을
가져가고 나중 곡에서는 제외되며 `DUPLICATE_ALIAS`가 보고됩니다. 한 번의 입력이 두
곡의 정답이 되는 상황을 만들지 않기 위해서입니다.

예를 들어 `사계 (Four Seasons)`와 `사계 (Winter)`가 함께 있으면, `사계`는 앞 곡의
정답이 되고 뒤 곡은 `사계 (Winter)`와 `Winter`로만 맞힐 수 있습니다.

남은 정답이 하나도 없어지면 그 곡은 `NO_USABLE_ALIAS`로 목록에서 빠집니다. 곡이 조용히
사라지는 셈이므로, 운영 화면에서는 검증 결과(`issues`)를 반드시 사람에게 보여 주어야
합니다. 그 화면은 아직 만들어지지 않았습니다.

## 6. 추출기 사용법

```powershell
python tools/extract-scx-song-text.py scenario.chk data/songs.recovered.json
```

- 입력은 `.scx` 원본이 아니라, StormLib 계열 MPQ 도구로 미리 꺼내 둔 `scenario.chk`
  입니다. 원본 맵은 파일명이 가려져 있어 바로 읽을 수 없습니다.
- 스크립트는 UTF-8로 읽히는 텍스트 구간만 훑어 `아티스트 - 제목` 형태를 찾습니다.
  오디오는 건드리지 않습니다.
- `아티스트 - 제목` 형태가 아니거나 한글이 하나도 없는 문자열, `Terran`·`Protoss` 같은
  게임 용어는 걸러집니다.
- 결과는 `{"count": N, "songs": [...]}` 형태로 저장되며, `mediaUrl`·`clipStart`·
  `clipEnd`는 항상 비어 있습니다.
- 같은 문자열이 여러 번 나와도 한 번만 기록됩니다.

## 7. 검수 체크리스트

곡 목록을 실제 게임에 올리기 전에 확인합니다.

**곡별 확인**

- [ ] 제목과 아티스트가 실제 곡과 맞는가 (복구 과정에서 잘렸을 수 있음)
- [ ] 제목 앞뒤에 `엔딩곡은`, `입니다` 같은 잔여 문구가 남아 있지 않은가
- [ ] 괄호 자동 확장 결과가 어색하지 않은가 (`4-1` 표 참고)
- [ ] 사람들이 실제로 부르는 이름이 정답에 포함되는가
- [ ] `mediaUrl`이 이용 허락을 받은 출처인가
- [ ] 재생 구간이 5~15초이고, 곡을 알아볼 수 있는 부분인가
- [ ] 재생 구간에 제목이 그대로 불리는 부분이 들어가 너무 쉬워지지는 않는가

**목록 전체 확인**

- [ ] `buildSongCatalog` 결과의 `issues`가 비어 있는가
- [ ] 남은 `playable` 곡 수가 한 판을 돌리기에 충분한가 (설정 최대 40곡)
- [ ] `DUPLICATE_ALIAS`로 빠진 곡이 있다면 의도한 결과인가
- [ ] 음원 주소가 곡명을 그대로 드러내지 않는가 — 파일명이나 페이지 제목으로 정답이
      새는 문제는 [`claude-analysis.md`](./claude-analysis.md) §7에 정리되어 있습니다.
